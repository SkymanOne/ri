# Status

Progress against the milestones in [AGENTS.md](../AGENTS.md). v0.1 is the completion of M7. Each milestone is delivered as a slice: its exit criterion is met on the subset stated here.

Intentional differences from pi, and the pi features not ported yet, are in [compat.md](../docs/compat.md). The deferred work below lists only what compat.md does not.

## M0: workspace, types, mock server

Done. The workspace builds and checks on Linux and macOS with `cargo deny`. `yapi-types` reads and writes every pi golden file byte-identically. `yapi-mock` replays cassettes, and `cargo xtask mock-sse` serves one to any client or records one through a proxy with credentials redacted.

## M1: wire APIs, print and JSON modes

Done.

- Wire APIs `anthropic-messages`, `openai-completions` (all thinking formats and compat flags), `openai-responses` and `google-generative-ai`.
- The pi-ai 1.0.0 catalog, generated by `cargo xtask models`, with `models.json` overrides and custom providers.
- Credentials from `--api-key`, `auth.json` (`!command`, `$VAR`), `models.json`, the environment, and ambient AWS and Vertex credentials.
- Print and JSON modes with piped stdin and `@file` arguments, and pi's argument parser.

Exit criterion. Scenarios match pi for text, thinking, tool calls with result turns, HTTP and mid-stream errors, incomplete and max-token stops, piped stdin and model listing. Six of them replay live OpenCode Go recordings made with pi as the client (`tests/fixtures/cassettes/opencode-go`), covering the Anthropic, Completions and Responses APIs with thinking and tool calls. The other cassettes are hand-written from the providers' documented stream formats.

Deferred: OpenAI grammar-constrained custom tools are sent as function tools.

## M2: agent loop, tools, sessions

Done.

- Agent loop with parallel tool execution, steering and follow-up queues, and `AgentHooks`.
- All seven built-in tools. `grep` and `find` run `rg` and `fd` as pi does, downloading them when missing unless offline.
- System prompt sections, context files, skills, prompt templates, and settings with project trust.
- Sessions as a JSONL v3 tree with migration, branching, fork, clone and tree navigation with branch summaries and labels. `--continue`, `--session`, `--fork`, `--session-id` and custom session directories.
- pi's recovery: auto-retry with backoff, overflow recovery, threshold and manual compaction with split-turn summaries.

Exit criterion. Scenarios compare stdout, stderr, requests and the session files each program writes, for new, continued, opened and forked sessions, retries, length stops, compaction, parallel tools and `@file` arguments. yapi writes pi's session files line by line and continues sessions pi wrote.

## M3: interactive TUI

Done.

- Fullscreen and regular renderers, raw input decoding, Kitty keyboard negotiation, terminal color queries and the system theme.
- pi's transcript components, the editor with autocomplete, and the model, thinking, fork, session and tree selectors.
- `/settings` with pi's items, search and submenus, `/scoped-models`, themes from every source pi reads, and project trust with `/trust`.
- The built-in slash commands and key bindings, `!` and `!!` commands, and HTML export whose `--export` output is byte-identical to pi's.

Exit criterion. Golden suites recorded from pi-tui cover keys, input splitting, the editor, themes, text layout, markdown and autocomplete. Terminal scenarios recorded from pi match its screens, covering startup, a tool-call turn, the model, thinking, fork and tree selectors, the session commands, completion, double escape and regular mode.

## M4: RPC, MCP, OAuth, remaining wire APIs

Done.

- RPC mode: pi's JSONL protocol with every command of `rpc-types.ts`, concurrent command handling and pi's exit codes.
- MCP: a port of pi-mcp over stdio and streamable HTTP, `mcp.json` from the agent directory and trusted projects, `yapi mcp add`, `remove` and `list`, and the built-in extension with `direct`, `deferred` and `hidden` exposure, the resource tools and `/mcp` status.
- OAuth: Anthropic, OpenAI Codex, Sign in with ChatGPT, GitHub Copilot, Kimi Code, Meta, xAI, OpenRouter and the Radius gateway. `auth.json` takes a lock compatible with pi's, so concurrent yapi and pi processes refresh a token once. `/login`, `/logout` and `yapi auth`.
- Every other wire API and provider in pi-ai 1.0: `openai-codex-responses`, `azure-openai-responses`, `mistral-conversations`, `bedrock-converse-stream`, `google-vertex`, Cloudflare, `pi-messages`, Anthropic workload identity federation, the llama.cpp router with `/llama`, classifier models and image models.

Exit criterion. Scenarios recorded from pi match for RPC prompts, queues, abort, session, bash, settings and model commands, MCP tools and `/mcp`, `yapi mcp`, `/login` and `/logout` screens, `yapi auth`, and each wire API. pi's `RpcClient` example drives yapi to the same output and requests as pi. Each OAuth flow passes against a mock authorization server (`crates/yapi-ai/tests/oauth.rs`), and the maintainer verified sign-in with real accounts. Bedrock, Vertex, Cloudflare and federation requests are checked against mock servers with bodies taken from requests pi made.

Deferred: pi's wait, before a codemode script runs, for the MCP servers it names that have not connected yet.

## M5: extension host, headless

Done.

- `yapi-js`: QuickJS-NG, Node shims, pi's extension API with pi's loading errors, and the vendored `pi-tui` and `typebox`. CI checks the committed artifact against its inputs.
- `yapi-ext`: one actor thread per instance, a compiled-component cache, compute and memory limits, restart after a trap, and grants for files, processes, network and environment.
- The host-side module loader: Node resolution, TypeScript stripping, ES module and CommonJS interop, and a transpile cache.
- Extension tools, commands, flags, events and actions in every mode, with errors reported as pi reports them.
- Packages: `yapi install`, `remove`, `update`, `list` and `config` with pi's arguments and settings entries, a built-in npm client without lifecycle scripts, and resource resolution checked against pi's on eight trees (`crates/yapi-core/tests/resolve.rs`).
- Native extensions: the Rust SDK in `guest/yapi-extension-api` with five examples, each tested in `crates/yapi-ext/tests/native.rs`.

Exit criterion. All 79 of pi's example extensions register the same tools (with schemas), commands, flags, shortcuts and event handlers as in pi, and fail with pi's messages where pi does (`crates/yapi-ext/tests/examples.rs`). The criterion asks for 90%.

### npm packages

`cargo xtask package-registrations` compares the most-downloaded pi packages with pi's registrations (`packages.mjs`). The list, `tests/fixtures/pi/packages/ranked.json` from `top-packages.mjs`, is npm's ranking of packages with the `pi-package` keyword by monthly downloads: the top 500 on 4 October 2026, followed by the most downloaded on 5 October that were not among them.

Each package installs and loads in a child process of its own, in pi and in yapi. File access is limited to a scratch directory, there is no process or network access during loading, and both get the same five environment variables. pi itself cannot run 26 of the first 526 there: 6 publish builds for other platforms only, Node's permission model stops 17, and 3 crash. The next packages on the list take their places, so each of the 500 has pi's result to compare with. A package that fails to install or load in yapi counts against yapi.

418 of the 500 work without errors: they load in yapi without errors and register the same as in pi. 43 of them have no extensions. 47 fail in both with the same error: 37 doompi parts that need the doompi host loaded first, and 10 that need a package, program or file that is not installed. Of the 35 that differ:

- Native addons or WebAssembly (11): context-mode, opencode-codebase-index, open-codebase-index and @shanepadgett/tau-agent, and seven that pi fails on too with a different error (sharp, libsql, wreq-js, the parcel watcher, imagescript).
- pi internals beyond the extension API (9): pi-fabric patches `ExtensionRunner`; @gotgenes/pi-subagents uses `createToolSearchExtension`; pi-multi-codex and pi-plus use `builtinProviders`; oira666_pi-subagent uses `createFauxCore`; pi-landstrip, pi-smart-router, pi-llama-cpp and @runfusion/fusion call static factories such as `ModelRuntime.create` and `SettingsManager.create`.
- `net.getDefaultAutoSelectFamilyAttemptTimeout` (3): pi-shipd-checks, opl-pi-sht, pi-web-agent. pi fails on them later with a different error.
- Both fail with different errors (3): pi-harness-runtime, doompi-workflow, pi-better-openai. Loads in yapi where pi fails (1): @amaster.ai/pi-task-scheduler.
- Fails only in yapi (3): pi-vertex-claude needs Node's deprecated `punycode`; @cueloop/pi reads Node's `navigator` global; supi-code-intelligence imports a type as a value.
- Registers differently (5): pi-crew and pi-retry register nothing; pi-free registers an extra `glob`; pi-docparser and pi-memory differ in tool details.

Deferred:

- `message_end` replacements, and `tool_call` handlers that change the call's input.
- Completions through pi-ai from extensions.
- `pi.sendUserMessage` expands prompt templates. `turn_end` carries only `turnIndex`, `message` and `toolResults`.
- `yapi config` does not install configured packages that are missing.
- Asynchronous host operations (timers, processes, HTTP) in the Rust SDK.

## M7: codemode, performance, import, release

Done.

- Codemode: each script runs in a fresh `yapi-js` instance without grants, holding only pi's prelude, so its globals behave and fail as in pi. Nested tool calls carry pi's ids, events and hooks. MCP servers with `codemode` exposure activate it.
- `yapi import pi` copies pi's agent directory and the current project's `.pi` into yapi's, keeping files yapi already has.
- A tag-triggered release workflow builds stripped binaries for Linux and macOS on x86_64 and arm64. Each `yapi-<target>.tar.gz` holds the binary and its license files, with no version in the name. `install.sh`, `curl | tar`, `cargo binstall --git` and `cargo install --git` install it. Linux releases build on Ubuntu 22.04, so they run with glibc 2.35 or newer.
- `yapi new` creates a native extension package from `crates/yapi/templates/extension`, which `cargo generate` also reads.
- `cargo xtask bench` measures startup, keystroke latency, memory and binary size against pi. [docs/performance.md](../docs/performance.md) has the results. The wasm engine starts only when an extension loads or a codemode script runs.

Exit criterion. Scripts cannot reach files, processes, the network, the environment, modules or host natives: `crates/yapi-ext/tests/codemode.rs` checks every global a script sees against pi's list and that imports fail. Three scenarios recorded from pi match: nested calls with the store, a script error, and the interactive rendering.

Deferred: the warning pi prints when a package's `codemode` replaces the built-in.

## Final end-to-end pass

Run on Linux x86_64 after the rename to yapi.

| Check | Command | Result |
|---|---|---|
| Live differential against pi `v1.0.0` | `cargo xtask e2e --differential` | As of the last differential run, all 245 scenarios then in the manifest matched, covering every wire API, sessions, compaction, the TUI, sign-in, MCP, packages, extensions with their UI, and codemode. |
| Workspace tests | `cargo test --workspace` | Pass, including every scenario against its recorded golden. |
| QA review | Agents drove yapi and pi side by side and compared screens, styles, requests, files and exit codes | Every finding is fixed with a regression test or a scenario recorded from pi, or listed in [compat.md](../docs/compat.md). |
| Lints, licenses, runtime artifact | `cargo clippy`, `cargo deny check`, `cargo xtask js-runtime --check` | Clean. |

QA once saw yapi exit with SIGABRT after writing all of its output, in 2 of about 190 RPC runs with an extension loaded. It was a race on Linux between extension threads and libgcc's exit-time unwinder cleanup. yapi now joins its extension threads before it exits (pull request `feature/extension-exit-abort`).
